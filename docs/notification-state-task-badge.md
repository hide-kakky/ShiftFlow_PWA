## 設定表示

これまで端末登録に成功しても、有効化ボタンの文字が「この端末で通知を有効にする」のままで、上の状態文だけが変わっていた。保存後も保存ボタンは同じ表示だった。

- 端末許可・購読・サーバー登録・通知サービス準備の判定を保ち、有効な端末はボタンにも「この端末の通知は有効です」と表示する。
- サーバーに保存された非0版があり、未保存変更がない場合は「保存済み」として重複保存を止める。未保存の初期0版は通常の保存を許可する。
- 設定を編集すると保存ボタンを再び操作可能にし、未保存の案内を表示する。保存失敗は成功扱いにせず、既存のversion競合・owner・世代保護を維持する。

これは設定欄の表示修正。通知状態を確認できていないのに、OS許可だけで有効とみなす修正ではない。

## タスク数字の意味

アプリ内の下部/PCタスクアイコンの数字は、**自分が担当し、期限が今日以前で、まだ完了していないタスク数**。新規タスクの未読件数ではない。今日が期限のタスクも含める既存仕様を維持し、aria-labelにもその意味を加えた。カードの「期限超過」は昨日以前だけを指す。

| 操作・状態 | アプリ内タスク数字 |
| --- | --- |
| 他の人からタスクを依頼される | 期限が今日以前なら、再取得後に増える |
| 新規依頼だが期限は明日以降 | 新規通知の対象でも、この数字は増えない |
| タスク一覧・詳細を開く／通知を開く | 未完了なら残る |
| 未着手から対応中へ変更 | 期限対象のままなので残る |
| 完了、削除、担当解除 | 再取得で対象から外れて減る |
| 期限を明日以降へ延期 | 再取得で対象から外れて減る |
| 対象が0件になる | 数字を隠す |

新規依頼通知は担当者が対象で、操作本人は通知されない。フォルダ設定、閲覧権限、購読、セッションを送信前に確認する。通知の到着だけでアプリ内数字を加算する実装ではなく、取得した実タスク状態から再計算する。未確認/既読の台帳はタスクには設けていない。

**iPhoneホーム画面のアプリアイコンの件数は現在未実装**。setAppBadge/clearAppBadgeはなく、SWのbadge画像指定は通知用画像である。通知センターの通知はタップ時にその通知を閉じる。タスク完了操作から既に表示した通知を削除する処理はない。OSによる表示管理や本人の消去は別の動作。

アプリを閉じたまま期限が来た時に数値を更新する機能や、期限超過専用の通知も今回追加していない。

## バッジ不具合と修正

引数なしの再集計はwindow.TASK_STATEを参照していたが、実体はconst TASK_STATEのため0件になる経路があった。また、空の担当一覧を古いHomeや別scopeの値へ戻すと、消えるべき数字が残る可能性もあった。

本人の担当一覧とHomeの担当分だけを使い、既存の取得時刻で新しい方を選ぶ。他人の担当や自分が依頼しただけのタスクは混ぜない。明示された空配列は正当な0件として扱う。新しいHomeで依頼を受けた時の増加、より新しい担当一覧で0件になった時の消去も検証した。
