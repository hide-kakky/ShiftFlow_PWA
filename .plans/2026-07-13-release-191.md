# ShiftFlow 1.9.1 本番デプロイ

## 現在のタスク

- `codex/mobile-chrome-navigation` の `APP_VERSION=1.9.1` を最終検証し、`origin/main` へfast-forwardで統合してCloudflare Pages本番へ反映する。

## 目的

- スマホ上部ステータスバー、下部メニュー位置、FAB配色、タップ遷移への統一を、Git正本とCloudflare Pages本番で同じcommitとして安全に公開する。

## 成功条件

- `frontend/public/app-config.js`、`frontend/public/sw.js`、READMEのversionが`1.9.1`で一致する。
- release blockerがなく、unit test、秘匿情報scan、Pages Functions build、Preview smokeが成功する。
- `origin/main` がrelease commitを含み、Cloudflare Pagesの最新Production deploymentが同じsource commitで成功する。
- canonical productionでroot、app-config、Service Worker、manifest、未認証session、主要headerをread-only検証する。

## 再利用した知識

- `cloudflare-deploy`: deploy前にWrangler認証、Pages project、production branchを実測し、deploy後にdeploymentとlive responseを確認する。
- `nonfunctional-release-guardrails`: production-facing releaseとしてbrowser、Pages Functions、OAuth、KV session、D1、R2、logsの境界を分離し、変更していない高リスク領域を明記する。
- `git-branch-safety`: remote-tracked work branchからのみ作業し、`main`はfast-forward統合とpushの対象に限定する。
- `plans-strategy-archive`: release結果をsanitized sealed snapshotへ固定し、current Planをidleへ戻す。
- 前回release記録: PreviewとProductionを分離し、PWA version、safe smoke、rollback targetを同じ証跡で閉じる。

## Scope

- `4c3c7b6`のUI差分と`APP_VERSION=1.9.1`のrelease検証。
- Cloudflare Pagesの既存Preview確認、`origin/main`へのfast-forward push、Git連携Production deploymentの監視。
- canonical productionのread-only smoke testとPlan固定保存。

## 非スコープ

- D1 migration、KV／R2データ変更、secret／環境変数変更、OAuth設定変更、backup Worker deploy。
- 認証済み実ユーザー操作、書き込みAPI、通知、メール、iOS／Android実機acceptance。
- 退避済み`.DS_Store`差分や無関係branchの整理。

## 実行計画

1. Git、Cloudflare認証、Pages project、Preview／Production deploymentを棚卸しする。
2. version同期、release guardrail、`npm run check`、Preview read-only smokeを通す。
3. work branchを`origin/main`へfast-forward pushし、Production deploymentの成功を監視する。
4. canonical productionをread-only smoke testし、release結果とrollback境界を固定保存する。

## 検証方法

- Static／Regression: `git diff --check`、version同期、`npm run check`、依存脆弱性scan。
- Cloudflare: authenticated Wrangler、project／deployment一覧、Preview／Production source commitとstatus。
- Production read-only: root、app-config、sw、manifest、`/auth/session`、security／cache headers。
- Git: `origin/main`、work branch、Production source commitの一致とclean worktree。
- 未検証境界は、実機表示、認証済み操作、データ書き込み、長時間monitoringとして分離する。

## 戻し方

- Cloudflare Pagesでは直前のsuccessful Production deploymentをrollback targetとして再昇格し、version／session／header smokeを再実行する。
- Gitではrelease commitを作業branch上で`git revert`し、PWA cacheの巻き戻りを避けるため新しい`APP_VERSION`を発行してから`main`へ反映する。

## 許可境界

- ユーザーの「デプロイして」という明示依頼により、既存差分の最終検証、`origin/main`への統合／push、Cloudflare Pages Production deploy、read-only検証まで許可されている。
- DB／KV／R2書き込み、secret変更、migration、OAuth設定変更、外部通知は許可範囲外。

## Git / 作業ツリー境界

- current branchは`codex/mobile-chrome-navigation`で、`origin/codex/mobile-chrome-navigation`をtrackingするremote work branch。
- 作業開始時点でcode commitはremoteと一致し、`origin/main`より1 commit先行・遅れ0。Plan更新以外の未コミット差分はない。
- `main`では実装を行わず、fast-forward統合とpush後の基準点確認だけに使う。
- 退避済み`.DS_Store` stashはrelease対象外として触れない。

## Test matrix

- static／unit／Functions build／secret scan／dependency audit: deploy前に実行。
- Preview smoke: production push前にread-only HTTPで実測。
- Production smoke: deployment成功後にread-only HTTPで実測。
- live data write／real auth／device acceptance／long monitoring: 未実施として分離。

## High-risk boundary

- 分類: production-facing feature release。
- trust boundary: browser ↔ Pages static assets／Functions ↔ OAuth／KV session ↔ D1 tenant data ↔ R2 attachments ↔ diagnostic logs。
- 今回の差分はmobile UI、navigation、PWA metadata、regression testに限定され、auth、authorization、DB schema、binding、secret、upload制約、external API behaviorを変更しない。

## Rizo接続

- 接続分類: `evidence_asset`
- 再利用した知識: production releaseではUI proof、Git source proof、release safety、rollback proofを分離する。
- 増える資産: ShiftFlowのスマホUI改善をGit正本から本番まで閉じた実績素材と失敗予防。
- 接続しないもの: production内部ID、secret、利用者データをRizo資産へ転記しない。
- 反省と改善: Preview source、Production source、canonical live versionを同じrelease証跡で一致させる。
